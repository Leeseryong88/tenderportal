# 관리자 운영 매뉴얼 (`ADMIN_GUIDE_KO.md`)

## 1. 회원가입 승인 · 역할 배정 · 협력사 연결 (`/admin/users`)
1. 사용자가 `/signup`에서 가입 후 이메일 인증을 완료하면 `PENDING` 상태로 목록에 나타납니다.
2. **Manage** 버튼을 눌러 다음 항목을 확인합니다:
   - 검증된 이메일(`Verified Email`) 및 요청 소속/역할(`Requested Role / Company`)
3. 실제 역할(`ADMIN`, `USER_DEPARTMENT`, `SUPPLIER`)을 배정합니다:
   - `ADMIN` 임명/수정은 소유 관리자(`canManageAdmins: true`)만 가능합니다.
   - `SUPPLIER`인 경우 **반드시 협력사 Pool에 등록된 정확한 회사를 선택**해 연결합니다(회사명 문자열 자동 매칭 없음).
   - 동일 회사의 다른 직원이 가입해도 별도 계정으로 개별 승인해야 합니다.
4. **Approve / Save Role** 클릭 시 관리자 비밀번호 재인증 창이 열립니다. 확인을 마치면 즉시 활성화됩니다.

## 2. 계정 사용 중지 및 회사 재연결
- **Disable**: 해당 사용자의 입찰 접근 grant가 즉시 비활성화되고 Firebase Auth 토큰이 폐기되며, 열려 있는 탭도 다음 요청에서 차단됩니다.
- **회사 재연결**: 다른 협력사로 소속을 변경하면 이전 회사 입찰에 대한 기존 `access` grant가 자동 회수됩니다.
- **마지막 관리자 보호**: 조직 내 마지막 활성 관리자는 삭제·강등·정지할 수 없습니다.

## 3. 협력사 Pool 및 지도 관리 (`/admin/suppliers`)
- 본사 소재 국가(`Head office country`)와 실제 수행 커버리지(`Service coverage`)는 별도로 관리됩니다.
- 미국 주별 커버리지(`US-TX`, `US-NY` 등)와 국가 전체(`United States`)를 함께 지정할 수 있으며, 특정 주 설정이 국가 전체 설정보다 우선 적용됩니다.
- `USER_DEPARTMENT` 계정은 `/department/suppliers`에서 승인된 디렉터리 정보와 커버리지만 열람할 수 있으며, 입찰 이력·제출자료·내부 메모에는 접근할 수 없습니다.

## 4. 프로젝트 · 입찰 · 일정 · 초청 관리 (`/admin/projects`, `/admin/tenders`)
1. **프로젝트 기본 일정**: 8단계 일정을 설정하면 해당 프로젝트의 입찰에 기본 상속됩니다. `미대상(NOT_APPLICABLE)` 또는 `공란(UNSET)` 선택 시 날짜는 비워지고 달력에서 제거됩니다.
2. **입찰 생성**:
   - `임시 저장(DRAFT)`: 미완성 상태로 저장되며 외부에 공개되지 않습니다.
   - `생성 완료(PUBLISHED)`: 미래 마감일·시간대(DST 자동 반영)·초청 업체를 검증해 공개합니다.
3. **입찰별 사용자 배정 & 초청 링크**:
   - 협력사 회사를 입찰에 초청했더라도 **입찰 상세 화면에서 해당 회사 소속 승인 계정을 체크 배정**하거나 **이메일 전용 초청 링크를 발급**해야 협력사가 입찰을 열람·제출할 수 있습니다.
   - 초청 링크는 대상 이메일·회사·입찰에 바인딩된 1회용 토큰이며, 관리자가 링크를 복사해 직접 전달합니다. 언제든 **Revoke**로 회수할 수 있습니다.
4. **제출 후 입찰 수정**:
   - 한 업체라도 서류를 제출한 뒤 입찰을 수정하면 경고 창이 표시됩니다.
   - 수정 저장 시 기존 제출자료·접수시각·접수번호는 모두 보존되며 `revision`과 변경 사유가 기록됩니다. 공개된 입찰은 다시 `작성 중(DRAFT)`으로 되돌아가지 않습니다.
